## Plugin API summary (v7.0.0)

There are no lifecycle hooks in the sense of event subscriptions. A plugin is an oclif command package.

- Registration: `package.json` has `oclif: { bin: "mm", commands: "./dist/commands", topicSeparator: " " }`, keyword `oclif-plugin`, and a manifest block:
  `mm: { schemaVersion: 1, minCliVersion: "^7.0.0", capabilities: [], commands: [{ id: "readset:safe-submit", capabilities: ["wallet-read","wallet-submit"], dataAccess: ["balances"] }] }`.
  Keep the plugin-wide `capabilities` empty (it merges into every command). Command file `src/commands/readset/safe-submit.ts` becomes `mm readset safe-submit`. Run `oclif manifest` and ship `oclif.manifest.json`.
- Class: `import { PluginCommand, CommandIO, InputFieldType, InputSchema, schemaToFlags, schemaToArgs, CommandError } from '@metamask/agent-wallet/plugin'`.
  - `abstract class PluginCommand<TFinal, TItem> { protected abstract readonly pluginCommandId: string; static requiresAuth = true; static requiresInit = true; }`
  - You implement `execute(io: CommandIO)`. Optional hooks: `afterExecute`, `successHint`, `analyticsOutcome`. Everything else is sealed (overriding a sealed member throws).
  - `io.resolveInputs(schema)` resolves flags, args and prompts.
  - `new CommandError(code, message, hint)` is the refusal channel; `mm` prints `{ok:false,error:{code,message,hint}}`.
- Context (`this.ctx`, type `PluginCommandContext`): `logger, authService, accountService, priceService, tokenService, networkRegistry, feesService, walletStateManager, swapQuoteStore, publicClient(chainId): viem PublicClient, walletExecutor(io, source, opts?): Promise<EvmWalletExecutor>, args, flags, argv`. Session, CLI token and mnemonic are host-only.
  - `walletExecutor` is gated by the `wallet-submit` capability. `publicClient` needs `wallet-read` and an authenticated session.
- Submit seam: `EvmWalletExecutor = (req, {signal?, noAwait?, waitForReceipt?}) => Promise<EvmWalletResult>`. Request: `{kind:'transaction', chainId, transaction: EVMTransaction, intent?}`. `EVMTransaction = {to, data?|functionName+abi+args, value?: bigint, gas?: bigint, gasPrice?, maxFeePerGas?, maxPriorityFeePerGas?, nonce?, options?:{speed}}`. Result `{kind:'transaction', hash, status, failureCode?, failureDescription?, pendingJob?, finalJob?}`.
- Policy: MetaMask backend policy and MFA still apply to plugin submits. Modes: Guard (allowlists, 24h outflow cap with 2FA) and Beast. `mm wallet policy get|set|template`.
- CLI: `mm config set experimentalPlugins true` (plugins are a beta, off by default); `mm config set experimentalAllowUnverifiedInstalls true` for local installs; `mm plugins install <npm-pkg> --accept-permissions`, `mm plugins link <dir>`, `mm plugins inspect|update|uninstall`. Install scripts never run. npm installs fail closed if the package cannot be verified.
- Plugins run in-process, unsandboxed.

## Gotchas found while building

1. Template's `minCliVersion: "^6.2.0"` fails on current CLI: `PLUGIN_CLI_VERSION ... requires CLI ^6.2.0; running 7.0.0`. Use `^7.0.0`.
2. `mm` needs Node 22.18 or later. This machine has 22.13.1, so I ran it with a scratch Node 22.23 (`npm i node@22` in the scratchpad).
3. On Windows, `plugins install file:D:\...` fails ("Invalid npm package name"). `plugins link D:/path --accept-permissions` works.
4. `tsconfig` for plugins needs `moduleResolution: "Bundler"`; the SDK's `.d.ts` files use extensionless imports and break under NodeNext.
5. Our `HOTSLOT_PRIVATE_KEY` cannot be imported. BYOK takes a BIP-39 mnemonic (`mm init --wallet byok --mnemonic`), and server wallet needs a MetaMask login. A funded test wallet must be one of those.
6. A plugin cannot stop an agent calling `mm transfer` directly. The gate only holds if the agent is told to use `mm readset safe-submit`.
7. Agent Wallet SDK licence is source-viewable only for now. Our plugin code is ours (MIT) and only peer-depends on it. Do not vendor or copy SDK code.

## Spike (all runnable, nothing mocked)

`packages/plugin/spike/mm-plugin/` is the plugin. Build: `tsc -p tsconfig.json && oclif manifest` (Node 22.18 or later on PATH). Install: `mm plugins link <abs path> --accept-permissions`.

- `mm readset gate --from F --to T [--value wei]` (`requiresAuth=false`) ran inside `mm` against Monad testnet. For the unfunded wallet it returned `INSUFFICIENT_FUNDS: balance 0 wei < gas_limit*price+value 2570400000000000 wei` and wrote a receipt. The gas-limit×price arithmetic is the Monad full-limit charge.
- `mm readset safe-submit --to T` stops at `AUTH_FAILED: No CLI refresh token available`. That is the first blocker: no MetaMask login.
- `packages/plugin/spike/direct-send.ts` (`npx tsx`, uses `HOTSLOT_PRIVATE_KEY`, never printed) runs the same gate on 10143, then signs with an explicit `gas`. Result: `REFUSED (nothing signed): INSUFFICIENT_FUNDS balance 0`. Testnet RPC confirmed chainId 0x279f (10143), balance 0, gas price about 102 gwei. After funding it sends a 0.001 MON self-transfer with the gated gas limit and prints receipt `gasUsed`.

What blocked: (1) wallet 0x28F0...90BA has 0 MON; (2) `mm` signing needs a MetaMask account login or BYOK mnemonic; (3) unverified that Agent Wallet's backend honours `gas` and supports 10143. Resolve (2) and (3) by logging in with `mm login browser`, then `mm chains list --json` and one `safe-submit`.

## Recommended Readset integration design

- Packaging: npm package `readset-agent-wallet-plugin` (publish it, since npm installs are the verified path), commands `mm readset safe-submit`, `mm readset status`, `mm readset policy`, `mm readset explain <hash>`. Core (`@readset/core`) is bundled, so the SDK stays a peer dependency.
- `safe-submit` flow (host runs auth first): load policy and breaker state; if breaker is tripped, throw `CommandError('READSET_BREAKER_TRIPPED', ...)` before any simulation; run the gate through `ctx.publicClient(chainId)` (simulate at latest, reserve and `gas_limit×price` check, gas limit from simulated gas plus Category Labs buffer); on doom, throw `READSET_REFUSED_*` with slot-level reason and write a refusal receipt; otherwise call `walletExecutor(io, id)(req with gas)` with `waitForReceipt: true`, then record the outcome and feed the breaker (revert streak, burn per hour).
- Receipts: JSONL file under the CLI config dir, one record per decision (allowed, refused, tripped), as already written by the spike.
- Breaker: state file with `maxConsecutiveReverts`, `maxBurnPerHour`, per (target, selector) limits; a `mm readset reset` command clears it.
- Agent routing: ship an agent skill (the docs reference https://github.com/MetaMask/agent-skills) that tells agents to use `mm readset safe-submit` instead of `mm transfer`. State plainly that this is cooperative, not enforced.
- Share the same core with the viem wrapper and MCP server; the plugin is a thin adapter.

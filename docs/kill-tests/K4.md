# K4: `monadNewHeads` / `monadLogs` reachable on a hosted endpoint

**Verdict: PASS.** Both subscriptions work on free public mainnet and testnet WebSocket endpoints with no API key. The fast-path fallback (cut it) is not triggered. No Alchemy/QuickNode/Dwellir keys exist in `.env` (it only holds `HOTSLOT_NETWORK` and `HOTSLOT_PRIVATE_KEY`), so keyed providers were not tested.

## Docs (fetched 2026-10-07)

- Block states: Proposed → Voted (QC) → Finalized (QC-squared) → Verified (execution output agreed, `latest_finalized - execution_delay`). Source: docs.monad.xyz/monad-arch/consensus/block-states.
- RPC tag mapping: `latest` = Proposed, `safe` = Voted, `finalized` = Finalized. `pending` behaves like `latest`. Verified has no tag. Source: /reference/rpc-differences.
- Responses based on non-finalized blocks can change on a repeated identical request.
- `newHeads` / `logs` fire at proposal time (speculative execution). `monadNewHeads` / `monadLogs` add `blockId` and `commitState`. `syncing` and `newPendingTransactions` are unsupported. Source: /reference/rpc-differences, /reference/websockets.
- The docs do not publish endpoint URLs for WS or the exact subscribe payload; both below are from live probing.

## Exact subscribe payloads

```json
{"jsonrpc":"2.0","id":1,"method":"eth_subscribe","params":["monadNewHeads"]}
{"jsonrpc":"2.0","id":1,"method":"eth_subscribe","params":["monadLogs",{}]}
```

`monadLogs` takes the usual `{address, topics}` filter; `{}` was accepted.

## Observed message shapes

Ack: `{"jsonrpc":"2.0","result":"0x<subId>","id":1}`.

Notification: `{"jsonrpc":"2.0","method":"eth_subscription","params":{"subscription":"0x..","result":{...}}}`. For `monadNewHeads` the result is a full header (`number`, `hash`, `parentHash`, `timestamp`, `gasUsed`, `baseFeePerGas`, ...; numbers are hex) plus `blockId` and `commitState`. For `monadLogs` it is a log (`address`, `topics`, `data`, ...) plus `blockId` and `commitState`.

Every block is emitted once per state, in this typical order (real capture, `packages/bench/test/fixtures/monad-newheads-mainnet.jsonl`, 326 frames in 25 s):

```
height 111213627 Voted      <- same instant as ->  111213628 Proposed
height 111213627 Finalized  (~150 ms later)        111213624 Verified
height 111213628 Voted      <- same instant as ->  111213629 Proposed
```

- A block is Voted when the next block is proposed.
- Finalized comes about 1 block after Voted.
- Verified trails Finalized by 3 heights.
- The first frames after connecting are late-state blocks (Finalized/Verified), so some blocks are never seen as Proposed.
- Headers carry `blockId` (distinct from `hash`). The state machine keys on `hash`.

## Abandonment definition (logger)

A hash H at height N that was seen Proposed is **abandoned** if a different hash is Finalized at N and H never is. Heights older than 24 finalized blocks are evicted and written as one `block` JSONL record. Outcomes:

- `finalized`
- `abandoned`
- `unresolved`: the socket ended before the height resolved.
- `partial`: first seen after the Proposed state, so excluded from the rate.

The rate is abandoned / (finalized + abandoned) among blocks seen as Proposed, with a Wilson 95% interval.

## Numbers so far (real run, mainnet, ~10.7 min, 2026-10-07 03:15 to 03:26 UTC, heights 111214083..111216167)

Collected over 3 sessions on rpc.monad.xyz, with 2 failed reconnects in between.

| Metric | Value |
| --- | --- |
| Blocks logged | 1744 |
| Finalized (seen as Proposed) | 1724 |
| Abandoned | **0** |
| Unresolved / partial | 5 / 15 |
| Abandonment rate | 0 / 1724 = 0.00%, Wilson 95% upper bound **0.22%** |

Latency in ms, from receive-time deltas on one socket (so it includes network jitter):

| Interval | p50 | p90 | p99 | max |
| --- | --- | --- | --- | --- |
| Proposed → Voted | 264 | 468 | 1736 | 6965 |
| Voted → Finalized | 238 | 413 | 1195 | 15405 |
| Proposed → Finalized | 530 | 764 | 3062 | 15807 |
| Finalized → Verified | 903 | 1225 | 4277 | 16085 |

The p99 and max values look like bursts after stalls or buffering. The hotslot measurement of ~305 ms block time is consistent with the ~2.5 blocks/s seen.

**Interpretation:** a 10-minute window cannot bound a rare event. This only shows the rate is below about 0.2% at 95% confidence. The 24 h run is needed before quoting "abandonment" on the benchmark page, and the report must say "observer-local, one public endpoint".

## Consequence for the PRD

- The fast path stays viable: `monadLogs` gives per-log `commitState`, so invalidation can be keyed to Proposed (fastest) or Voted.
- `monadLogs` only sees events, so the miss-rate audit for silent state changes is still required.
- `latest` simulation is on Proposed state; the data above suggests abandonment is rare. Confirm over 24 h.
